It fixes nothing else, shortens every red by about seven minutes of runner time, and would also fail the slow installs that did finish (457 s on 2026-10-24, 410 s on 2026-10-25).

Options 1 and 2 are independent; 1 alone would have answered today's question about the suite. Nine workflows carry the install line, and a change to any of them is a change to infrastructure (Rule 39): the dependency map above is the start of it, and the consumers still have to be audited.

The install and its job must carry no `continue-on-error` (that is the shape, and needs all of it), an annotation above no install is stale, and a file that installs on a line the text cannot match (a continuation, a folded scalar) or is not valid YAML is refused, not skipped. The annotation is a drift guard and a statement of why the skip is right; it does not make it right. N also counts what else the failure skips: the jobs that `needs:` the install's job (through a skipped one too) whose `if` is not certain to run, and for a composite action the steps that follow it in every job that calls it and the jobs that need those (`mutation-equivalence.yml`'s `compare` needs two callers of `mutation-shard` and runs on `always()`, so it adds nothing; the step after the action in `mutation-ids-probe.yml` adds one).
