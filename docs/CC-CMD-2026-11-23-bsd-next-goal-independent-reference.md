## The rule, fixed before the run

**Step A, source against source (no ledger).** For every match in R2 that E2 puts on exactly one archive row, compare ESPN's goal list with FIELD's BSD capture: same number of goals, same order of sides, same minutes within 1. Counts only: matches compared, identical, different in number, in order, in minute.

**Step B, the ledger against ESPN.** For each of the 372-class calls (the census's gradeable calls, taken at run time) on a match E2 puts on exactly one archive row whose ESPN final score equals the capture's (its `espn_event_id` is the ESPN match; no name join is run here): k = the total of `score_at_call`; ESPN's resolving goal is its (k + 1)th goal in clock order; ESPN's side is that goal's scoring side (an own goal credited to the beneficiary, per E3); FIELD-independent verdict is `hit` if that side equals the call's `side`, else `miss`; the call **agrees** when the verdict equals the ledger's `outcome`. The join must also hold: ESPN's score before that goal equals `score_at_call`, else not applicable. Every call lands in agree, disagree or one named not-applicable reason, including E2's named reasons (`league outside the join's sports`, `before 2026-10-24, no joined row that day`, `other unjoined`, `two or more rows`, `final score differs`) and "the match has no ESPN timeline". Agree and disagree are tallied by league, by whether ESPN and BSD's capture agree on that goal (from step A), and by distance between ESPN's goal minute and the ledger's `resolved_minute`.
A disagreement is a count and a named reason, never explained away (Rule 77). No probability is graded.

## What the result will not say

Different vendors are not proof of independent origin: ESPN and BSD may license one provider's feed. Step A is the evidence either way (E5), and the artifact reports it beside the grade. A match ESPN does not cover is not graded, so the result is about the calls on matches both sources have. It says nothing about the probabilities or about whether a call was a good prediction.
