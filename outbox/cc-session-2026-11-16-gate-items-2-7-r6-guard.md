### P4 (pre-existing false RED, REACHABLE-low; reviewer): a backtick or `$(` inside SINGLE quotes is refused as a command substitution

`echo 'run `npm run gate` locally'` in the required no-browser step, or in any step the guard reads, was refused with `a command substitution inside a word`: `split_commands` tested each shlex token for a backtick or `$(`, and a token has already lost its quotes. (An unquoted `$( )` is not that case: shlex splits it into `$`, `(` and the commands inside, which are read as commands.) `blank_single_quoted` replaces the content of each single-quoted string by `_` (double-quoted text is left, because a substitution in it runs; a backslash outside single quotes escapes the next character; an unterminated quote leaves the rest), the same line is tokenised a second time, and the test is made on that second reading's words. The two readings have the same words, because a single-quoted string is one word whatever it holds; if their counts ever differ the real words are tested. My first version tested the whole line instead of the words and broke five checks (an unquoted `$(seq ...)` in a wait loop, `D=$(mktemp -d)`, a `printf` with a `$(date ...)`): the harness of this guard said so at once, and it is reverted, not patched. Fixtures: five single-quoted texts read clean, eight substitutions that run stay unresolved (a double-quoted one with the message, an unquoted one through the command inside it), and the helper's output on three inputs. Table: `browser-gate-subst-single-quotes-not-blanked`, `-backtick-ignored`, `-dollar-paren-ignored`, `-blank-single-reads-double`, each `PASS`. Population (402 `run:` steps, both guards in-process): 2 steps read differently (`deploy.yml`, `odds-shape-census.yml`, each with fewer reasons), 0 changed `browser` flag, 127 of 127 `package.json` bodies identical.
