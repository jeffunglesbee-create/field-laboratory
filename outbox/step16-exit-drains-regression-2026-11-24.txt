3. CAUSE
--------
The --self-test branch I added to scripts/schedule-live-check.mjs in 77647dc1 ended with

    process.exit(summarize() === 0 ? 0 : 1)

and the live half of the script (the browser launch) came after it. That is an EARLY report exit by the definition in
scripts/check-exit-drains.mjs: a process.exit(summarize(...)) with code after it. The check freezes the count at the
number in docs/early-exit-budget.txt (63) and fails when it grows. brief-phase-live-check.mjs holds three of the 63;
I took the pattern from there because finish() sets process.exitCode and does not stop, and the self-test must not fall
through into a browser. The header of check-exit-drains.mjs names exactly that trade-off. I did not run the check
that counts the choice.

Why it got through, each read from the file named:
  - My own list before the commit was sixteen gates I chose by hand. check:exit-drains was not on it.
  - .githooks/pre-commit runs twelve `npm run` lines (clean-source, workflows, staged-outbox, staged-verifier,
    boundary, import-purity, mutation-anchors, citations, short-circuit, setup-script, browser-gate, push-lands).
    It does not run check:exit-drains. 77647dc1 passed the hook; its first attempt was refused by
    check:staged-outbox, for a different reason (source staged with no outbox entry), and the second was not.
  - The confidence gate (npm run gate, 23 rows, docs/gate-rows.txt) has no row for it either. Quick mode scores
    230/270 = 85/100 on 77647dc1 and on 6e32367a alike, with the same two rows red (section 6f).
  - The only place check:exit-drains runs is verify's step 38, after the push.


4. NOT DONE, AND WHY
--------------------
  - docs/early-exit-budget.txt was not raised to 64. The check's second FAIL line says "lower the budget to 64",
    which is only the arithmetic of equality. The header says the count may not grow, and gives the measurement behind
    that. A number edited to match the new exit turns the ratchet off.
  - The exit was not re-spelled so the pattern misses it (a variable between summarize() and process.exit). The
    REPORT_EXIT expression matches `process.exit(summarize(` and `process.exit(ss(`. Hiding the call from the counter
    keeps the hazard it counts (process.exit drops pending stdout writes to a pipe) and removes the only thing that
    sees it.
  - finish(summarize()) in place was not used: it does not stop, so the self-test would run on into the browser.
