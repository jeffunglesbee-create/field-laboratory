## What Task 2 asked for

> the sentinel reports line SHAPE across the whole slate and never reports
> which SPORTS carry odds.

Every odds counter in `drift-check.mjs` before this change — `both`, `notseq`,
`moved`, `unmoved`, `spreads`, `unbal`, `totals`, `split`, `mismatch` — counts
games that **have** odds. The whole family therefore shares one blind spot: a
sport that stops receiving any prices shrinks the denominator, and the surviving
games still report healthy shapes. MLS going from two-way prices to 0 of 17 rows
would have registered as a quieter but perfectly healthy run.

### The alarm's shape, and what it deliberately does not do

It fires on a **transition**, not a level: a sport that carried odds on an
earlier committed reading and now carries none on rows that exist. It does not
fire on a sport that has never carried odds (Bundesliga, CFB, CFL, NFL on both
captured dates). That is a coverage decision rather than a regression, and a red
nobody is permitted to clear is a red everybody learns to skip — the same
argument the claim sweep's STALE handling already makes.

It also does not fire on a sport with zero rows. Out of season is not starved.

### The write guard

Only a `--url` run appends to the series. A `--file` replay is a real payload
but not a new observation, and letting one append would let any replay re-date
the history the alarm reads. `--seed` is the one deliberate exception, and it
exists so the committed history is **generated by the same `censusOf` the alarm
reads** rather than hand-written.

## The defect this session made, and what it changed

The first `outbox/odds-coverage-series.json` was hand-written. Both entries
carried `sports: {}`.

`transitions()` is right to ignore an empty reading — there is nothing to have
lost — so the alarm went silent, and the check printed:

```
PASS  no sport lost odds coverage it previously had
```

over a history that was **incapable of failing**. That green is
indistinguishable from the green a healthy slate produces. It survived a full
gate run and was caught only because the alarm had fired minutes earlier, from
a series the pre-guard code had written, and then stopped.

Same shape as the five rows in this repo's CLAUDE.md: the seed was a **copy** of
the capture, locally true-looking, and nothing regenerated it from the source.

Three things changed as a result:

1. `--seed` regenerates the history from the captures through `censusOf`, so a
   hand-written seed is no longer the mechanism.
2. `vacuousReadings()` names any committed reading carrying no sports, and
   `drift-check` checks it **separately from the alarm** — the denominator is
   now asserted, not assumed.
3. `O7` mutates `vacuousReadings` to accept everything and confirms the check
   goes red. Caught.

Restoring the empty seed, end to end:

```
FAIL  the committed coverage history is not vacuous
      → readings carrying no sports: 2026-08-29, 2026-09-05 —
        regenerate with --file <capture> --seed
PASS  no sport lost odds coverage it previously had
12/13 checks passed
```

The second line is the vacuous green, now sitting beside the red that explains
it.

## Coverage of this work — what it does NOT establish

The demonstration above uses the **two committed captures, 2026-08-29 and
2026-09-05**. Both **pre-date** the odds-layer changes on 09-12, 09-14, 09-16
and 09-19. Nothing here says anything about the current slate.

The CC-CMD's done condition — MLS appearing with 0 odds — is **not met by this
work**, and is not evidence either way: on both captured dates MLS carries heavy
three-way prices (26/28 with 26 draws, then 18/21 with 18 draws), which is also
a different characterisation from the CC-CMD's description of MLS as two-way.
Those captures are earlier than the CC-CMD's 09-06/09-10 window, so this is a
different window, not a contradiction. The live census is what would settle it.

`drift-sentinel` runs the live probe twice daily and now writes a real reading
each time. The first live run is the first datum about the current slate.
