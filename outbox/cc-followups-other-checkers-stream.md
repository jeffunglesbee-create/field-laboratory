CC-CMD: `docs/CC-CMD-2026-11-03-gate-hazard-residuals.md`, item 19 of Task 10, the paragraph "other checkers" (`scripts/short-circuit-check.mjs`, `scripts/check-script-orphans.mjs`, `scripts/check-lineups-pull-only.mjs`). ## short-circuit-check.mjs: comments blanked by the scanner

- Premise command, run before building: plant `run('a') && run('b')` at every statement start that begins a line (code per acorn) of every `scripts/*.mjs`, and ask the real exported `offences()` whether it sees one more. Red: 81 of 16,281 positions missed (0.50%), in 10 scripts (`lineups-live-probe` 21, `check-script-orphans` 14, `check-ignore-parity` 13, `history-check` 11, `nav-check` 11, `checks` 4, `claim-check` 4, `outlet-scan-check`, `pickem-check`, `spark-check` 1 each). Two mechanisms were read off the missed lines: a glob string that holds `/*` (`'/**'` in `check-ignore-parity`) pairing with a later `*/` in another string, and a line comment that holds `src/*.js` (`history-check`) opening a block comment that ends at the next doc comment.
- Built: `offences()` blanks with `blankComments`, a new export of the shared module (comments only; strings, regular expressions and a template's `${...}` stay, because the guard's subject is code). A span is a comment if it starts with `//` or `/*`, which needs no change to the scanner; the module's blank now goes through one private `blankSpans`, so `exit-blank-keeps-every-span` is re-anchored (and shown caught again).
- After the change the same sweep misses 0 of 16,289. The old and the new offence lists over all 169 scripts are both empty (nothing in the tree was hidden); `blankComments` equals acorn's comment mask on 169 of 169 scripts except line 1 of the 23 `#!` scripts. The blank keeps line feeds, so an offence is reported on its source line (the old chain deleted a multi-line block comment and reported every later line too low).
- Clauses: `short-circuit-check.mjs --self-test` 4 to 8. Against the old stripper the two new fixture clauses fail (3 of 4 unseen; 1 of 4 on another line, `[[3,[2]]]`), and pass after. Two more pin what must not be taken. 6 table entries, each applied in a scratch copy and run through `mutation-check.mjs --ids`, each caught by the clause it names.
- Not covered (Rule 91): the fixtures are four whole files, not the tree (the tree's own scan is the check's live half). One conjunct of the comment predicate (the span starts with a slash) has no clause in this commit; it is pinned with the next consumer. A banned form in a string is still flagged, as before. The paren-in-string shape (`run('x)') && run('b')`) is a different blindness, in the rule's `[^)]*`, and is left alone (Rule 69).

## check-script-orphans.mjs: edges read after the same comment blank

- Premise commands, run before building. Lost-edge sweep: plant `run('node scripts/zzz-planted.mjs')` at every statement start of every `scripts/*.mjs` and ask the real exported `stripJsComments` plus `scriptFiles` whether the edge is there. Red: 88 of 16,289 positions missed (0.54%) in 11 scripts (81 of 16,281 in 10 at the start of the session; the 11th script is `short-circuit-check.mjs`, whose own header, written one commit earlier, quotes `'/**'` and `src/*.js`: the hole moves with the text around it). The other direction: plant a COMMENT that names a script, `void 0;// scripts/zzz-planted.mjs`, and require that it is not an edge. Red: 16,201 of 16,289 positions read it as one (the old rule strips `//` only at a line start or after whitespace), and a comment alone on its line is never read (0 of 16,289).
- Built: `stripJsComments` is `blankComments` from the shared module, with a comment that says what the old pair of regular expressions got wrong in both directions. Strings are kept because the edges are in them. After the change the same three sweeps miss 0, 0 and 0 of 16,297. Over all 169 scripts the edge sets of the old and the new differ in two scripts (`generate-team-colours.mjs`, `venue-sourced-check.mjs`), each a self-edge the new one keeps, and in this file's own fixtures (`ghost.mjs`, a file that does not exist); no comment in the tree was read as an edge by the old one (0 gained), so reachability is unchanged and the live run reads 168 reachable, 3 of 3.
- Clauses: `check-script-orphans.mjs --self-test` 14 to 18. Against the old stripper the two new fixture clauses fail (3 of 3 edges not seen; 1 of 3 comments read as an edge, `["real.mjs","ghost.mjs"]`); two pins pass on both (a string that merely begins with `//` or `/*` keeps its edge, an edge in a template literal stays). 4 table entries, each applied in a scratch copy and run through `mutation-check.mjs --ids`, each caught by the clause it names. The two pins close the gap the previous entry left: the predicate's "starts with a slash" conjunct now has a clause (`comment-blank-takes-slash-strings`).
- Not covered (Rule 91): the fixtures are small whole files; the rest of `edgesOf` (the `existsSync` filter, `importsOf` on the raw text) is unchanged and untested by these clauses. `importsOf` reads imports from the raw text with a regular expression, so an import named in a comment is an edge; not measured, not touched.

## check-lineups-pull-only.mjs: F# comments read by a scanner of its own

- Premise commands, run before building. The guard scans F#, so no JS tokenizer applies; the truth here is the F# compiler's own line tokenizer (`FSharpLineTokenizer`, through `dotnet fsi` with the SDK's `FSharp.Compiler.Service.dll`), which marks each character of each source as comment, string or code. Plant at every line start the tokenizer calls code (617 positions in the four regions the guard reads; 18,581 in all 49 `src/*.fs`) and ask the real exported `codeOnly` plus `recurrencesIn` whether a `setInterval` is seen. Five shapes: a plain timer (P1), a `//` inside a string then a timer (P2), `"(*"` and `"*)"` in strings around a timer (P3), a timer inside a nested comment which must NOT be seen (P4), a `//` inside a block comment then a timer (P5). Red, old stripper: P1 0 of 617 wrong (0.0%); P2, P3, P4 and P5 617 of 617 wrong (100%); the same on all 49 files, 18,581 of 18,581 for P2 to P5, and 0 for P1. Reading it: no position in the real tree defeats the old stripper for a plain timer (the tree has no `(*` and its two `//`-in-a-string lines end their line), so the tree is safe today; the four shapes are lost wherever they are put.
- Built: `codeOnly` is a scanner (`//` and `///`, nesting `(* *)` whose strings and character literals are read as such and in which `(*)` neither opens nor closes, strings of every kind including verbatim, triple-quoted and interpolated with holes, and character literals), blanking comments to spaces with line feeds kept. Strings are NOT blanked: `[<Emit("setInterval($0, $1)")>]` carries a timer in a string (the tree has one `Emit("""...""")`), and the visibility rule matches a string. Its comment blank equals the F# tokenizer's on 49 of 49 sources (495,798 comment characters) and on 20 of 20 fixture files (the self-test's, plus a file of tricky forms); the one-off is not a test in the repo. After the change the same plant sweep is wrong at 0 of 617 positions for all five shapes in the four regions, and 0 of 792 (every 25th line start) in all 49 files. The scan of the four regions finds the same recurrences as before (none).
- Clauses: `check-lineups-pull-only.mjs --self-test` 25 to 29. Against the old stripper (the entry `lineups-comments-by-regex` puts its two expressions back) the timer-seen clause fails 10 of 12 fixtures and the timer-in-a-comment clause flags 2 of 7. Rule 90 found five of the first nineteen entries surviving: a string that a mutant over- or under-extends is not blanked either way, so the difference only shows where a comment follows it; the fixtures were reworked (a quiet one after each string form: verbatim backslash, verbatim doubled quote, escaped brace, escaped-quote character) and all nineteen, plus one for the line feeds, are caught, each by the clause it names.
- Not covered (Rule 91): the numeric and Unicode escapes of a character literal (`'\065'`, `'A'`, `'\U...'`) have no fixture, because a mutant that drops them changes nothing unless a quote is spelled that way; an unterminated string or comment (it runs to the end of the text and no further) has no clause; `$$"""` strings, a `$"` inside a comment and `#if` regions are read as the compiler reads them or as text, and none occurs in `src/`. The guard still reads four regions, not the repository, and says so where it prints.
