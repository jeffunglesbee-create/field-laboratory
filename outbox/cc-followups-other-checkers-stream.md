## short-circuit-check.mjs: comments blanked by the scanner

- Premise command, run before building: plant `run('a') && run('b')` at every statement start that begins a line (code per acorn) of every `scripts/*.mjs`, and ask the real exported `offences()` whether it sees one more. Red: 81 of 16,281 positions missed (0.50%), in 10 scripts (`lineups-live-probe` 21, `check-script-orphans` 14, `check-ignore-parity` 13, `history-check` 11, `nav-check` 11, `checks` 4, `claim-check` 4, `outlet-scan-check`, `pickem-check`, `spark-check` 1 each). Two mechanisms were read off the missed lines: a glob string that holds `/*` (`'/**'` in `check-ignore-parity`) pairing with a later `*/` in another string, and a line comment that holds `src/*.js` (`history-check`) opening a block comment that ends at the next doc comment.
- Built: `offences()` blanks with `blankComments`, a new export of the shared module (comments only; strings, regular expressions and a template's `${...}` stay, because the guard's subject is code). A span is a comment if it starts with `//` or `/*`, which needs no change to the scanner; the module's blank now goes through one private `blankSpans`, so `exit-blank-keeps-every-span` is re-anchored (and shown caught again).
- After the change the same sweep misses 0 of 16,289. The old and the new offence lists over all 169 scripts are both empty (nothing in the tree was hidden); `blankComments` equals acorn's comment mask on 169 of 169 scripts except line 1 of the 23 `#!` scripts. The blank keeps line feeds, so an offence is reported on its source line (the old chain deleted a multi-line block comment and reported every later line too low).
- Clauses: `short-circuit-check.mjs --self-test` 4 to 8. Against the old stripper the two new fixture clauses fail (3 of 4 unseen; 1 of 4 on another line, `[[3,[2]]]`), and pass after. Two more pin what must not be taken. 6 table entries, each applied in a scratch copy and run through `mutation-check.mjs --ids`, each caught by the clause it names.
- Not covered (Rule 91): the fixtures are four whole files, not the tree (the tree's own scan is the check's live half). One conjunct of the comment predicate (the span starts with a slash) has no clause in this commit; it is pinned with the next consumer. A banned form in a string is still flagged, as before. The paren-in-string shape (`run('x)') && run('b')`) is a different blindness, in the rule's `[^)]*`, and is left alone (Rule 69).
