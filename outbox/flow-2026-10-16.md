## Measured first (Rule 100)

Before any type: a premise pass over every capture in R2, run on a
field-relay-nba runner (the sandbox cannot reach workers.dev). Every number is
from one run, 38963130231, 789 captures; they are under Task 1 in the CC-CMD.
The four that changed the build:

1. `xg` is null on 123 of 21,055 rows (9 captures) and **0 on none**.
2. Stoppage is `min` + `added` at 105 as at 45 and 90, so 106 is a sound
   boundary.
3. BSD writes the full-time marker at 90' **before extra time as well**: FT
   sits beside an extra-time marker in all 17 extra-time captures.
4. Every capture carries its `event_id`, and every event row its kickoff.

## What an adversarial review changed, before any commit

A reviewer attacked the first build in a copy of the tree. Each finding below
was reproduced, then fixed:

- **A full-time witness could unlock a match still in play.** The first build
  gave the witness to a capture showing FT at 90' with no extra-time marker. By
  premise 3, a knockout match captured in the break before extra time has
  exactly that shape. The full-time route is gone; the kickoff route covers
  every capture.
- **The state leaked.** It was an opaque value with a `ToString` override, but
  Thoth's `Encode.Auto` printed `["Reads",["InFlow",0.42]]`, Fable reflection
  read the private case, and boxed equality ordered two states. It is now a
  private type that no public function returns.
- **One match's stats could borrow another's full time**, because the two
  files' event ids were never compared. They are now.
- **Two mutations proved nothing.** `flow-live-marker-wins` survived (its row
  was also refused by another rule), and `flow-witness-goes-public` did not
  compile, which the harness scores as caught. Both were rebuilt, and then the
  live-marker rule itself went with the full-time route.
- **Census arithmetic:** a gap across two periods counted one boundary, a run
  ended by a 0-xG shot was counted under two closers, and the null-xG check
  was an inequality that passed at zero. All three fixed, each with a row.

## A tooling hazard found on the way

A Fable build in a `cp`'d copy of this repo reads the copied
`build/fable_modules/project_cracked.json`, which names THIS tree's absolute
source paths, so it compiles this tree's `src/` and not the copy's. That also
explains the "module 'Flow' is not defined" builds seen here while three
copies were compiling. Delete `build/fable_modules/project_cracked.json` (in a
copy: `rm -rf build src/obj src/bin` and `dotnet restore`) before trusting a
build or a mutation run, because mutation-check scores a tree that does not
build as caught.
