## Facts read from primary sources (kept, with what each leaves open)

- A composite action's step takes no `timeout-minutes`: GitHub's metadata-syntax page lists run, shell, if, name, id, env, working-directory, uses, with and continue-on-error, and `actions/runner`'s `action_yaml.json` agrees. A `timeout-minutes` on the calling `uses:` step bounds the whole action, so it cannot be the install's limit. Fractional values are not supported and `0` means no limit.
- `playwright install chromium` never runs apt, dpkg, sudo or su (strace A/B with a positive control: `--with-deps` made 1 `apt-get` and 3 `dpkg` execves, the plain install none); its network dependency is `cdn.playwright.dev` (and `playwright.download.prss.microsoft.com` for ffmpeg). It is three downloads of up to five attempts each with a 30 s socket idle timeout, so a CDN that connects and stalls could outlast 180 s; the limit ends it at 180 s.
- Playwright 1.62.1's launch-time dependency check scans `chrome-linux/`, which the x64 Chrome-for-Testing build does not have, so it passes without checking anything. A missing library does not warn at install time; it shows as `error while loading shared libraries` at the first step that launches the browser. The `ldd` premise is the measurement that stands in for it on this image.
- The runner's `timeout` is uutils coreutils 0.10.0 (Ubuntu 26.04 moved coreutils to uutils): with `--kill-after` a clean TERM exit still exits 124 there, where uutils 0.0.24 (the only version obtainable in the sandbox) printed 125; any non-zero exit fails the step.
