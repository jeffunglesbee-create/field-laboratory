10. WHAT THIS DOES NOT ESTABLISH
--------------------------------

- The new message on a real refusal in a live session. Unobserved. The harness replays shrunk, grown and missing trees in scratch worktrees, and on this commit's own hook run the clause only passed. Read it the next time the equality clause fails in a session with the hook: the output prints `FAIL  ...and the budget is not loose` with the detail under it, and no commit exists.
- The runner. The steps of verify and guards on the pushed head are read after the push and recorded in the session record, not here.
- A raise caused by a scanner change. For a grown count the message says what to do when an exit was added. When the scanner itself was fixed to count more (c362be57), the budget does go up, and the message does not say how. That is a decision, and A4 shows the hook accepts it when both files agree.
- Two parts of the new wording are not pinned by a clause. The instruction in the missing-file message ("write the count into it") is not tested; the path and the word "missing" are. And "which are among those listed above" depends on the clause above the equality clause listing every early exit under the words "the new one(s) are among:". That sentence is built inline in the live check, and no self-test clause reads it, so a change to it would not fail one.
- A budget lowered by more than one at a time. The shrunk message gives the number to set as `find`, and the entry's `replace` (64) stays above any lower count, so it should work the same way. Only 63 to 62 was run.
- The proof ran in scratch worktrees that use the main tree's installed node_modules after the package files are shown identical (the harness asserts it per case). A fresh session's own install was not exercised.
- `git commit --no-verify` skips the hook, and so this message.
