# `check:live` failed on a slate with no venue, and that is not a coverage gap

**2026-08-25.** verify run 137 red on `53a0a7e`, a commit that touched no venue
code.

## What failed

```
FAIL  the venue table covers at least one venue on this slate
      → TBC — none of them in the 45-entry table
FAIL  every card whose venue the table knows carries a live chip
      → 0 known venue(s) on this slate, 0 chip(s) filled
FAIL  every live chip reads as a temperature and nothing else  → []
FAIL  every live chip carries a real roof caveat  → []
```

The four golf assertions added in the same commit series all passed, as did the
seventeen others.

## The slate, measured

`GET /context/date/2026-08-25`, probed 2026-08-25 via the relay self-probe:

```json
"games": { "regular": [], "postseason": [ {
  "id": "MLS_MLS-COM-000006_QF-01_quarterfinals_2026-08-25",
  "sport": "MLS", "round": "Quarterfinals", "league": "Leagues Cup",
  "home": "Club León", "away": "Real Salt Lake", "venue": "TBC" } ] }
```

**One game. Zero regular games. Its venue is the string `TBC`.**

The run fired at 05:25 UTC — 01:25 ET, so the FIELD day had just rolled over to
a slate consisting of one unscheduled Leagues Cup quarterfinal.

## Why this is not the failure it was reported as

`TBC` is the relay's placeholder for a venue that has not been decided. A
weather chip for it is impossible in PRINCIPLE, not missing from the table:
there is no such place. Adding `TBC` to `Venues.all` would be inventing a
location, which is Rule 1.

The check's own comment already reasons correctly about the neighbouring case:

> `expected === 0` is a VACUOUS pass and is asserted against directly. With no
> known venue on the slate, `filled.length === expected` is 0 === 0 and all
> three checks below go green having proven nothing.

That is right for a slate carrying real venues none of which are in the table.
It does not distinguish a slate carrying **no venue at all**, and the two were
collapsed into one failure. Only the first is one.

## The fix: a denominator, not a tolerance

```js
const PLACEHOLDER_VENUES = new Set(['TBC', 'TBD', '—', '-', ''])
const realVenues = vs => [...new Set(vs)].filter(v => !PLACEHOLDER_VENUES.has((v || '').trim()))
```

Three states, the same discipline this repo applies everywhere else:

- **≥1 real venue** → assert coverage exactly as before. Unchanged.
- **cards, but every venue a placeholder** → skipped, with a `::warning::` that
  prints the card count and the venue strings, so a slate that is quietly all
  placeholders for days is visible rather than inferred.
- **no cards** → already covered.

This is the same shape as the golf follow-up probe's denominator earlier today,
and the same mistake in reverse: there, "no PGA Tour row" would have read green
from absence; here, "no venue" read red from absence.

## The loosening is guarded, because a wrong skip is invisible

A skip that is too broad prints a warning and passes — nothing objects. So the
predicate is asserted on enumerated cases, in `check()` calls that run on EVERY
slate including ones where the skip never fires:

| case | real venues | meaning |
|---|---|---|
| `['TBC']` | 0 | the slate that caused this |
| `['TBC', 'Fenway Park']` | 1 | a placeholder beside a real venue is still observable |
| `[]` | 0 | an empty slate |
| `['Some Unlisted Park']` | **1** | **a real venue absent from the table IS still a coverage gap** |
| `[null, '  TBD  ']` | 0 | null and surrounding whitespace are placeholders |

Row four is the one that matters: it is the assertion that this change did not
delete the check it was widening.

## Not a golf regression

Stated plainly because "unrelated" is the rationalization Rule 77 forbids, and
it needs evidence rather than assertion:

- The four golf assertions passed in the same run.
- The diff in `53a0a7e` touches `cc-cmd-followup.mjs`, a CC-CMD doc and two
  outbox files — no venue, weather, or `Venues` code.
- verify 136 passed all four weather checks 2.5 hours earlier against the
  2026-08-24 slate, which carried real venues (Comerica Park, Fenway Park,
  Bellerive Country Club).
- The 2026-08-25 payload above is the direct cause and was probed, not inferred.
