## What was found, and how it was measured first (Rule 100)

`scripts/check-script-orphans.mjs` read the whole workflow text for `scripts/X.mjs` and counted every mention as an edge. A `paths:` entry is a trigger, not an invocation, so deleting the run line of a workflow that kept the script in its filter left the guard green (reproduced on `.github/workflows/uefa-fit-mutate.yml`: `PASS  3/3`). Before designing, with PyYAML over all 63 workflows: 234 mentions of a script, 231 in `run:` scalars and 3 in filters; the detector and the parser name the same 114 scripts; no script is named only in a filter; the 229 invocation-shaped run mentions and 2 that are not never leave a script with only non-invocation mentions. So no stricter definition moves any script out of the reachable set (210 before and after) and the ledger needed no change.

## What was built

`scripts/check-script-orphans.mjs`: `stripPathFilters`, `stripYamlComments`, `workflowText` (exported) and the reader's helpers (`startsToken`, `skipQuoted`, `endOfFlowSequence`, `endOfFlowScalar`, `endOfBlockSequence`, `endOfNextLineValue`, `removeFilterValues`). Inside a workflow's top-level `on:` block only, the value of a `paths` or `paths-ignore` key is removed, in these shapes: a block sequence (dashes at the key's indent or deeper, an item's deeper lines belonging to it), a flow sequence on one line or several, a scalar, any of those starting on the line after the key (the form Prettier writes), after an `&anchor`, a `!tag` or a verbatim `!<tag>`, and inside a flow-mapping `on: { ... }`. Flow context is tracked by depth, not by where a line starts; a quoted key may stand straight before its colon there. A key is a key only when its colon ends it (`paths:x` is one plain scalar). Left whole: a `paths:` key whose value is a mapping (an input of that name), the body of a block scalar, any `paths:` text outside `on:`. A quote opens only where a scalar can start, an `&anchor` or `!tag` in front of it not counting (an apostrophe in `description: Don't run` is text); `''` is an escaped apostrophe in a single-quoted scalar. A comment inside `on:` is dropped, a block scalar's header comment included; elsewhere a trailing `#` still reads as text. CR, CRLF and a BOM are normalised. The guard's main block reads the workflows through `workflowText`, one text per file.

Not covered, each measured absent from the 63 workflows and each documented in the guard's header: an explicit key (`? paths`); a flow collection continuing in column 0; a second document in a file; an indented document; a quote character that begins a continuation line of a multi-line PLAIN scalar (read as the opening of a quoted scalar; the result is a lost edge, a false orphan, and the guard says so loudly); a multi-line quoted scalar in a block list whose continuation lines are indented less than its dash; anchors, aliases and merge keys (a filter list reused through `*alias`); a script named by a trailing `#` comment outside `on:` or by an action input (`with: filters:`).
