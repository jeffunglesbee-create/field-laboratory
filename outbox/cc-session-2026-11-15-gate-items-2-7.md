## Item 4: `scripts/run-steps.mjs` counts the skips behind the failing step

`stepSummary` counted every skipped step as "behind" the failing one. With the Chromium gate's final step the failing step is the LAST one, so the twenty browser checks that did not run were reported as "did not run behind it" when they ran (were skipped) before it. Now `skipped` counts only the steps after the first failing step, in the job's own order, `skippedBefore` counts those before it, and the line says both (`Nothing was skipped behind it ... 20 steps before it were skipped by their own if`). `scripts/status.mjs`'s clause carries the before-count too. Self-test 19 of 19 (a fixture shaped like verify run 43158658704: the install behind `continue-on-error`, twenty browser steps skipped, the last step failing), `status-verdict-check` 41 of 41, `mutate-run-steps.mjs` 12 of 12 (S2 and S6 re-anchored, S8 to S12 added).

## The review of items 2 to 7 and what it changed (work in progress; the figures are final only where they say so)

An independent read-only review (4 reviewers over the guard, the harness, the gate modes and the rest, then two skeptics per finding, 48 agents) reported 22 findings; 20 survived both skeptics, 2 split. None is a false green on `main` today; each is a way a later edit could have gone green over a red. Every one is fixed with a check that fails without the fix:

- **Guard** (`scripts/check-browser-gate.py`): an unreadable `always()` step is kept as opaque only when the reader has not seen it launch a browser and it is not a `uses:` step; a spawned script is found by any path form (`./x`, `../x`, `${ROOT}/scripts/x`, `new URL('./x', import.meta.url)`, `scripts/sub/x`) and an import specifier is not a spawn; `scripts/confidence.mjs` and `scripts/run-row.mjs` are declared as running the gate's rows (they read as browser steps by that, not because a log message names a script); a step carrying the no-browser flag may run only what carries it; a target must run its no-browser spawner (`confidence.mjs --browserless` in `full`, `mutation-check.mjs --no-browser` in the shard action); the callers of the shard action are audited again (the exempt-site arithmetic was lost when it became a target); the gate rows are read by a closed grammar (a row it cannot read is a problem, never "browser-free"); the final step may read another step's outcome and is run for each pair of outcomes; hyphenated step ids are read. The tracked `scripts/__pycache__/*.pyc` is gone and ignored.
- **Harness**: `run-row.mjs` prints why a row failed (the four expectations that are `run-row` rows were failing baselines under `--no-browser`, not holes), and the gate's kept-lines filter keeps Playwright's launch line; the harness's own `--self-test` is never read as a missing browser; the equivalence report carries its `problems`.
- **Gate modes**: the exit is a pure `exitFor` that every exit of `confidence.mjs` goes through (pinned by a truth table and a source check; three one-line regressions had passed the old test), the closing line counts only the rows not run for want of a browser (6 / 180 points, not 7 / 190 on a scheduled run), the final step says the browserless gate ran only when its step succeeded, the citable-run count leaves out browserless records.
- **Trap, ranking, deletion**: `no-launch-check.mjs` has one runner for controls, fixtures and the 69 commands, a real exit-status test over a child run of itself, `launchServer`/`_electron`/`_android` in the stub, a Node-version guard that can be reached, and a scan of `scripts/` for a child started with a `NODE_OPTIONS` that replaces the trap's (`proof-check.mjs` did it twice; fixed). `worstFailure` ranks by every step that did not run, before and behind the failing one. `delete-branches.mjs` deletes by full ref (a tag of the same name no longer stops it), continues past a failure, names it, and ends through a pure `exitFor`.
