## The defect the real hook found in the first version of the self-test

The self-test passed standalone and FAILED under the pre-commit hook (the first commit attempt was refused): `everTrackedPaths` inherited `GIT_DIR` from the hook, which in a LINKED WORKTREE (where these sessions work) names the real repository, so it read the real history while being asked about a fixture. The fixture's own git commands had been given a cleaned environment; the reader under test had not. A hook in a plain checkout sets `GIT_INDEX_FILE` (relative) and `GIT_PREFIX` and no `GIT_DIR` (measured by a reviewer, git 2.43.0), so there the first version would have passed; the first version of this note and of the code comments said "under the pre-commit hook GIT_DIR names the real repository" and were corrected. Fixed by an `env` option on the reader; the self-test now poisons its own process environment, and the sweep runs under a decoy of the hook's environment and under a clean one. A standalone run cannot see this class of defect.
